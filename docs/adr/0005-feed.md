# ADR 0005: Feed and reels

The feed policy in `mpx_player` decides what plays, with sound or not, and what
preloads in a scrolling surface; the list and pager widgets that apply it live
in `mpx_ui`. It has two modes on one knob set: `list`, where every
visible clip plays muted, and `pager`, where one item plays with sound and its
neighbours stay warm. Preload is staged by distance and direction. The policy
reads no platform state; signals come through one host seam, and `mpx`'s
device signals are their default source.

**Status**: Accepted (decided with the maintainer 2026-11-10)
**Relates to**: 0001, 0003, 0004
**Amended**: 2026-11-13, package homes (ticket 27)

## Context

In the reference client's chat and channel history no item is "active": every
visible video autoplays muted on the software decoder and loops, and frames
advance only when painted (Android stops advancing below 25% visible). One
player app-wide has sound; a round video with sound moves to PiP when it
scrolls off. Stories, the reels analogue, play one item, keep ±1 warm and up
to two prepared players, gated to high-class devices with at least 8 HEVC
decoder instances. Preload is windowed and staged by distance; neither mobile
client predicts from scroll velocity. Media3 and Meta practice agree on one
active item, ±1 neighbours and back-off under stress.

## Decision

### Modes

| Mode | Behaviour | Player tier |
| --- | --- | --- |
| `list` | Every visible clip plays muted and loops; frames advance only when painted | Software decoders (`mpx_video_decoder`); a player only for the sound owner |
| `pager` | One active item with sound; ±1 warm; at most 2 prepared players, taken over on swipe | `mpx_player` pool |

One knob set serves both, with per-mode defaults.

### Knobs

The 25 knobs of research `05-feed-policies` §7 are the seam, each
with its reference default; the host overrides any of them. Groups:

| Group | Knobs (research numbering) |
| --- | --- |
| Selection | 1 mode, 2 active-item rule |
| Autoplay and sound | 3 autoplay gate (`none` / `prefixOnly` / `full`), 4 size limit, 5 muted autoplay, 6 sound owner, 7 initial mute, 8 off-screen behaviour of the sound owner, 9 auto-advance |
| Preload | 10 window, 11 stage by distance, 12 oversize prefix (a duration), 13 cancel on leave, 24 story-tray preload |
| Players | 14 prepared pool size, 15 start buffer, 16 forward buffer cap |
| Memory | 17 heavy-part unload distance, 18 inline resolution cap |
| Quality and stress | 19 quality choice, 20 stress back-off, 21 pause layers |
| Per surface | 22 resume position, 23 loop |
| Diagnostics | 25 hooks |

The sound owner (6) and the prepared-player budget (14) come from
the player pool (ADR 0004), in the same package; the feed fills the policy.

### Preload

| Area | Decision |
| --- | --- |
| Staging | By distance and direction: next item 5 s, previous 3 s, further items metadata only |
| Cancel | Everything outside the window is cancelled |
| Velocity | Only stretches the window ahead for the cheap stages (metadata, first frame). Nothing heavy starts during a fast scroll |
| Oversize | A duration prefix, resolved to bytes through the container index (ADR 0002 fast start) |

### Signals

| Area | Decision |
| --- | --- |
| Seam | `FeedSignals` in `mpx_player` takes the host's `ValueListenable`s (network class, power saving, thermal state; mapped by name from `mpx`'s enums) and yields one `FeedConditions` snapshot; file size is on each `FeedItem`. It also yields `metered`, `powerSaving` and `stressed` for the core's `PlaybackActivity` |
| Default adapter | Device signals in `mpx` (Android, iOS, macOS) expose network class, power-saving mode and thermal status as `ValueListenable`s |
| Wiring | No package below `mpx` depends on them. The stack feeds the core's pause layers (`lowPower`); the host passes them to this seam and anything else |
| Rules | The autoplay rule and the size limits are host knobs with reference defaults |

### Core additions this needs

A visible fraction on bindings, staged preload requests with priority and
cancel, network and power inputs on the pause layers (ADR 0003).

## Why

- The reference's split (many cheap muted loops, one expensive player) is what
  keeps a long history smooth; a single active item in a chat list would stop
  every other clip.
- Staging by distance is where the reference and Media3 agree; the maintainer
  allowed velocity to stretch only cheap stages because they cost bytes, not
  decoders.
- A host seam for signals keeps the package testable and lets a host that
  already tracks network or power feed it without a second plugin.
- Signals in the composition root serve the feed, the core's pause layers and
  any other consumer without making any of them depend on a platform plugin.
- The policy is rules over the player pool (prepared budget, sound owner,
  preload stages), so it lives with the pool; widgets are optional UI beside
  the viewer.

## Rejected

| Alternative | Why not |
| --- | --- |
| One active item in lists | Not the reference; stops all other visible clips |
| Velocity-driven heavy preload | Starts decoders the user scrolls past |
| Fixed byte prefixes | The reference's own lesson: express a prefix as duration |
| The feed reading platform state directly | Untestable; duplicates host state |
| Warmed player per visible item | Decoder-instance limits; Meta moved away from it |
| The adapter inside `mpx_player` | Ties device reads to one consumer; the core's pause layers need them too |
| Policy and widgets in one feed package | A package that is half pool rules, half UI |

## Consequences

- A host with lists only still takes `mpx_player` for the sound owner and the
  policy, and `mpx_ui` for the widgets unless it draws its own.
- Hosts without `mpx` bring their own signals.

## Open in implementation

- Defaults the reference does not give: the active-item visible fraction (0.5
  is a suggestion, not a reference value).
- Device-class detection on Apple (the Android gate is high device class and
  ≥8 HEVC instances).
- Mute behaviour from the ringer / silent switch on iOS and the volume-key
  unmute: knob 7 holds the rule; whether the platform read joins `mpx`'s
  device signals is not decided.
- The list widget is `FeedListView` (one item extent;
  it measures visible fractions from the scroll offset and applies a
  `FeedListPlanner` plan); the policy is `FeedPolicy.list` / `.pager`. The
  pager is `FeedPager` (mpx_player: leases the active item and up to
  min(knob 14, the pool's prepared budget) neighbours inside the window,
  nearest first, ahead before behind; a swipe plays the warm lease) and
  `FeedPagerView` (mpx_ui: a `PageView` of `PlayerView`s with the poster as
  stand-in). The device-class gate on the prepared budget is the host's
  `PlayerPool.budget` (ticket 28).
- The cap and measure of the velocity stretch: v1 has no stretch; a fast
  scroll (the core's `fastScroll` layer) only downgrades heavy stages to
  metadata.
